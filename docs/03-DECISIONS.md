| ADR-030 | 2026-10-05 | Accepted | Platform rules and format presets are seeded from researched public sources with **source, confidence (high/medium/low) and verified date per row**. The rule engine (`src/lib/rules`) is dependency-free and shared by server and browser; X weighted counting is implemented in-house (no twitter-text). | A stricter limit can never produce a post the platform rejects; recorded sources make every number checkable; no new dependency for ~40 lines of counting. |
| ADR-031 | 2026-10-05 | Accepted | Brands: configuration (create, edit, CGP/profile, channels, archive) is **owner-only**; editors read. Brand websites accept only `http(s)` URLs. | ADR-032 | 2026-10-05 | Accepted | Platform data editing (TASK-004b): super admins edit platform rules and format presets in `/admin/platform/*` through `src/server/rules/admin.ts` — validated (whole numbers, visible ≤ caption max, min ≤ max, safe zone leaves ≥ 1 px, verified date not in the future), row-locked, one `audit_log` row (`platform_rule.update` / `format_preset.update`) with `{field: {from, to}}` per changed field; unchanged saves write nothing. Key, platform, placement and media of a preset are fixed; presets are **disabled, never deleted** (later generations reference keys); no new rows from the UI yet. **Quarterly re-verification** = a row whose `verified_at` is **≥ 90 days old** is due; v1 reminder is an in-app banner on `/admin` and `/admin/platform` plus a per-row badge (no email/cron yet — no scheduler exists). | Platform specs change; editing must be safe and traceable. | ADR-033 | 2026-10-05 | Accepted | Brand file uploads (TASK-005b, refines ADR-006): uploads go **through the app** (not presigned PUT) so bytes are checked before they are stored. Type from **magic bytes** only (PDF, OOXML docx/xlsx/pptx by ZIP part names, PNG/JPEG/WebP, TTF/OTF, UTF-8 text; CSV vs text by name since both are text). **No SVG** (script risk) and no legacy .doc/.xls/.ppt, no WOFF/WOFF2 (Satori). Images are decoded and re-encoded by sharp (metadata stripped, ≤ 40 MP input, logos PNG ≤ 2048 px, others PNG/JPEG ≤ 4096 px). Fonts are parsed in-house (cmap/name); a brand writing `sl` refuses fonts missing any of `č š ž ć đ Č Š Ž Ć Đ`. Limits: logo/font 10 MB, source 50 MB; per brand 10 logos, 20 fonts, 200 sources; same file twice per brand = duplicate (sha256 of the upload). **Tenant separation:** keys `org/<orgId>/brand/<brandId>/<kind>/<uuid>.<ext>` built only from verified ids; rows (`brand_sources`, `brand_assets`) are the source of truth and are read only via `forOrg`; URLs are presigned (default 5 min, max 15) only after the row is found in the caller's org. Upload/delete = brand owner; read/download = any member. S3 put then row insert; a failed insert deletes the object; delete removes the row first. Local/CI S3 stand-in: moto server (MinIO no longer publishes community images). | The owner requires strict per-organization separation; checking content server-side is the only way to keep executables, scripts and decompression bombs out; in-house sniffing/font parsing avoids three dependencies for ~250 tested lines. |
| ADR-034 | 2026-10-06 | Accepted | Smart uploads (TASK-005c, refines ADR-033 on owner feedback): one drop zone for everything. The server sorts each file (fonts → fonts, images with "logo" in the name → logos, rest → sources; a "Dodaj logotip" button forces the logo slot). A plain **ZIP is unpacked server-side** with hard limits (≤ 200 files, ≤ 50 MB each, ≤ 300 MB total, ZIP ≤ 100 MB, inflation capped regardless of headers; encrypted/ZIP64/nested ZIPs refused per entry). **WOFF and WOFF2 are accepted** and converted to TTF/OTF on upload (WOFF in-house, WOFF2 via `wawoff2`, MIT) because the renderer needs TTF/OTF; this supersedes the "no WOFF/WOFF2" part of ADR-033. SVG stays refused. The diacritics requirement and note apply only to brands with `sl`. A channel's language must be one of its brand's languages. | Owner: brands ship web fonts and folders of assets; sorting files by hand was poor UX; an English brand got Slovenian defaults. Conversion at upload keeps rendering simple (one font format). |

| ADR-036 | 2026-10-06 | Accepted | Post generation v1 (TASK-007, refines ADR-007/010/015): **text posts are generated inside the request** (server action, ~5–20 s), not via pg-boss — the worker arrives with image/video jobs. Claude via the official SDK with a **forced `submit_post` tool** (JSON validated by zod), brand block (CGP, pillars, materials) **prompt-cached**. | ADR-037 | 2026-10-06 | Accepted | CGP from a document (TASK-008, implements the "both ways" part of ADR-035): the owner uploads a DOCX/PDF/MD/TXT (≤ 20 MB) or picks one of the brand's uploaded sources; its text is extracted **verbatim, without AI** and put into the CGP editor; nothing is stored until the owner saves a new profile version.

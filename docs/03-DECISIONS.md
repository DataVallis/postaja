# Postaja — Decisions (ADR log)

Append-only. Never delete a row; supersede it with a new ADR. Newest decision wins.
Status: Proposed · Accepted · Superseded by ADR-XXX · Open.

| ADR | Date | Status | Decision | Why / trade-offs |
|---|---|---|---|---|
| ADR-001 | 2026-10-05 | Accepted | Product name **Postaja**. Hosted on an owner subdomain (datavallis.com / davidtacer.com / aibuilders.si — final host Open). | postaja.si is taken; a subdomain is enough for v1. Revisit domain before phase 3 (selling). |
| ADR-002 | 2026-10-05 | Accepted | Hosting on **Hetzner Cloud with Kamal 2** from day one. No Vercel, no Supabase. | Owner already runs Hetzner; no later migration; no free-tier pausing; long-running jobs (image/video, rendering) have no serverless timeouts. Trade-off: we run backups and ops ourselves. |
| ADR-003 | 2026-10-05 | Accepted | **PostgreSQL 16 + pgvector**, **Drizzle ORM** + drizzle-kit migrations. | One database for app data, queue and vector search; Drizzle is portable and type-safe. |
| ADR-004 | 2026-10-05 | Accepted | **Better Auth** with organization and admin plugins. | Self-hosted, Drizzle adapter, built-in orgs/members/invitations and a superadmin role. |
| ADR-005 | 2026-10-05 | Accepted | Multi-tenant: shared DB, `org_id` on every tenant table, app-level scoping via `forOrg(ctx)` + mandatory cross-tenant integration tests. RLS later. | Simplest model that sells; tests prove isolation. RLS adds a second layer once the schema settles. |
| ADR-006 | 2026-10-05 | Accepted | **Hetzner Object Storage** (S3 API), private buckets per environment, presigned URLs ≤ 15 min. MinIO locally. | Same provider, S3-compatible, cheap egress within Hetzner. |
| ADR-007 | 2026-10-05 | Accepted | Background jobs with **pg-boss** and a separate `worker` Kamal role from the same image. No Redis. | Fewer moving parts; transactional enqueue with app data. |
| ADR-008 | 2026-10-05 | Open | Embedding provider: OpenAI `text-embedding-3-small` vs Voyage AI. Behind an `embeddings` adapter. | Decide on cost + Slovenian quality with a 50-post test set. Fixes the `vector(N)` dimension. |
| ADR-009 | 2026-10-05 | Accepted | Text on images is **always rendered by Postaja** (Satori → resvg → PNG), never drawn by the image model. | Image models misspell text, especially č/š/ž; brand fonts must be exact; editing text must not cost a regeneration. |
| ADR-010 | 2026-10-05 | Accepted | LLM: **Anthropic Claude API** behind an `llm` adapter, JSON output validated with zod, prompt caching for the brand block. | Strong instruction following and Slovenian; adapter keeps the provider swappable. |
| ADR-011 | 2026-10-05 | Accepted | Images, video and LoRA training via **fal.ai** behind a `media` adapter. Models are data (model registry), chosen per brand/persona, not hard-coded. | Model landscape changes monthly; switching a model must not need a deploy. |
| ADR-012 | 2026-10-05 | Accepted | Persona consistency = **DNA** (structured description) + **passport images** (3–10 references, one primary) passed to reference-capable models; optional LoRA. | Works with today's reference/edit models; LoRA as an upgrade path. |
| ADR-013 | 2026-10-05 | Accepted | Super admin is a **user flag** (`role = superadmin`), not an org role. Data Vallis is an ordinary organization on plan **`comped`**. | Owner uses the product exactly like a customer; admin powers stay separate and audited. |
| ADR-014 | 2026-10-05 | Accepted | v1 has **no direct publishing**: export (files/ZIP/PDF) + manual "mark published". | Platform APIs (X paid, LinkedIn restricted, Instagram Graph needs business accounts) are not worth it for the MVP. |
| ADR-015 | 2026-10-05 | Accepted | Money and costs stored as **bigint micro-USD**. | No floats for money; provider prices can be fractions of a cent. |
| ADR-016 | 2026-10-05 | Accepted | Post types: `text` (incl. X thread), `single_image`, `carousel` (default 6 slides), `video` (persona, phase 2). | Covers all current brands; video waits for persona work. |
| ADR-017 | 2026-10-05 | Accepted | Host: **`postaja.inzenirji.si`** (prod), `dev-postaja.inzenirji.si` (dev). Supersedes ADR-001 "final host Open". | Owner's choice; name stays Postaja. |
| ADR-018 | 2026-10-05 | Accepted | Brand CGP is **built by AI from any uploaded sources** (PDF, DOCX, XLSX/CSV, PPTX, text, images, URLs). Output is a reviewed **proposal** with source references and conflict questions; only the owner's accept creates a profile version. The template is optional. | Owners already have brand material in many forms; filling forms is the main onboarding friction. Proposal + accept keeps the owner in control and blocks prompt injection from documents. |
| ADR-019 | 2026-10-05 | Accepted | Post types extended: `animation` (animate any image via image-to-video) and `ad` (ad set rendered per placement). `video` covers all short video posts (text-to-video, image-to-video, multi-shot); persona video is `video` + persona. Supersedes ADR-016 type list. | Owner needs animated posts, video posts and ads, not only persona video. |
| ADR-020 | 2026-10-05 | Accepted | **Format presets are data** (`format_presets`, super-admin editable) with exact sizes, safe zones and copy limits. Every output is validated against its preset. Aspect changes use smart crop or outpaint — never stretch. | Platform specs change; wrong dimensions must be impossible, not just unlikely. |
| ADR-021 | 2026-10-05 | Accepted | Text, logos, CTA buttons and subtitles on **video** are burned in by Postaja (Satori overlay PNG + ffmpeg), extending ADR-009 to video. Clean (overlay-free) image and video assets are always stored. | Same reasons as ADR-009; clean assets make text edits, animation and recompose free of regeneration cost. |
| ADR-022 | 2026-10-05 | Accepted | **Every output** passes three rule layers — platform (global `platform_rules` + `format_presets`), channel, brand — most strict wins; checked in prompt, after generation and live in the editor by one shared rule engine. Hard violations block `ready` unless overridden with a logged reason. | Classic posts must be as compliant as ads: dimensions, caption length, hashtag count. Platform limits change, so they are data. |
| ADR-023 | 2026-10-05 | Accepted | **Competitor research**: AI finds competitors via web search; collects only public, ToS-respecting sources (web, Meta Ad Library API, public pages) plus owner-uploaded screenshots; no login scraping. Learnings are adopt/reject items the owner approves into a CGP proposal. Generated posts are checked against competitor posts to avoid copying. | Learn from competitors without legal/ToS risk or plagiarism; owner stays in control of the CGP. |
| ADR-024 | 2026-10-05 | Accepted | Database migrations run **at container start** of the `web` role (`RUN_MIGRATIONS=1` → `drizzle` migrate, then server). Replaces "Kamal pre-deploy hook" in `02-ARCHITECTURE.md` §9. | Kamal hooks run on the deploying machine, not next to the DB; running in the new container is simple and keeps migrations tied to the image. Migrations stay backward compatible (expand → migrate → contract), so the old container keeps working during the switch. |
| ADR-025 | 2026-10-05 | Accepted | **dev runs on the owner's existing Hetzner VM** (4 vCPU / 8 GB / 80 GB, user `deploy`), shared with an existing app (must stay) and later volil.si. One kamal-proxy for all Kamal apps on the host; each app has its own service name, its own DB accessory without published ports, memory limits, and named volumes. Prod gets its own VM before launch. | Cheapest start; 8 GB is enough for web + Postgres + light worker. Video/LibreOffice work (phase 1b+) may need the worker on a separate VM. Requires ports 80/443 to be free for kamal-proxy (TASK-002 checks the existing app). |
| ADR-026 | 2026-10-05 | Accepted | On the shared server **kamal-proxy owns ports 80/443** (automatic Let's Encrypt per app); host nginx is retired. Every app on the host is deployed with Kamal: Postaja dev, volil.si, and **asisto is migrated to Kamal**. Transitional step: asisto-api is registered in kamal-proxy by hand until its own Kamal config exists. Supersedes the "nginx in front" option. | One proxy, one deploy tool, zero-downtime deploys and automatic TLS for every app; no hand-edited nginx/certbot per domain. Cost: a few minutes of asisto API downtime at cutover (asisto is not in active use) and a one-time migration. Nginx config is backed up and can be restored in minutes. |
| ADR-027 | 2026-10-05 | Accepted | **Supersedes ADR-026.** On the shared dev server **host nginx stays the edge** (80/443, certbot TLS). kamal-proxy runs behind it on `127.0.0.1:8080` only (`ssl: false`, `forward_headers: true`); nginx gets one `server` block per Kamal app (`dev-postaja.inzenirji.si`, later volil.si) proxying to it. asisto is not migrated. Postaja prod and volil.si prod get their own Kamal-only servers (kamal-proxy on 80/443). | The asisto repo shows `asisto.app` and `portal.asisto.app` are Laravel on host PHP-FPM — kamal-proxy cannot serve them without containerising two unused apps. Nginx in front changes nothing for asisto, costs one nginx block + certbot per new domain on this box only, and keeps prod servers clean. |

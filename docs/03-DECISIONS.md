| ADR-011 | 2026-10-05 | Accepted | Images, video and LoRA training via **fal.ai** behind a `media` adapter. Models are data (model registry), chosen per brand/persona, not hard-coded. | Model landscape changes monthly; switching a model must not need a deploy. |
| ADR-012 | 2026-10-05 | Accepted | Persona consistency = **DNA** (structured description) + **passport images** (3–10 references, one primary) passed to reference-capable models; optional LoRA. | Works with today's reference/edit models; LoRA as an upgrade path. |
| ADR-013 | 2026-10-05 | Accepted | Super admin is a **user flag** (`role = superadmin`), not an org role. Data Vallis is an ordinary organization on plan **`comped`**. | Owner uses the product exactly like a customer; admin powers stay separate and audited. |
| ADR-014 | 2026-10-05 | Accepted | v1 has **no direct publishing**: export (files/ZIP/PDF) + manual "mark published". | Platform APIs (X paid, LinkedIn restricted, Instagram Graph needs business accounts) are not worth it for the MVP. |
| ADR-015 | 2026-10-05 | Accepted | Money and costs stored as **bigint micro-USD**. | No floats for money; provider prices can be fractions of a cent. |
| ADR-016 | 2026-10-05 | Accepted | Post types: `text` (incl. X thread), `single_image`, `carousel` (default 6 slides), `video` (persona, phase 2). | Covers all current brands; video waits for persona work. |
| ADR-017 | 2026-10-05 | Accepted | Host: **`postaja.inzenirji.si`** (prod), `dev-postaja.inzenirji.si` (dev). Supersedes ADR-001 "final host Open". | Owner's choice; name stays Postaja. |
| ADR-018 | 2026-10-05 | Accepted | Brand CGP is **built by AI from any uploaded sources** (PDF, DOCX, XLSX/CSV, PPTX, text, images, URLs). Output is a reviewed **proposal** with source references and conflict questions; only the owner's accept creates a profile version. The template is optional. | Owners already have brand material in many forms; filling forms is the main onboarding friction. Proposal + accept keeps the owner in control and blocks prompt injection from documents. |
| ADR-019 | 2026-10-05 | Accepted | Post types extended: `animation` (animate any image via image-to-video) and `ad` (ad set rendered per placement). `video` covers all short video posts (text-to-video, image-to-video, multi-shot); persona video is `video` + persona. Supersedes ADR-016 type list. | Owner needs animated posts, video posts and ads, not only persona video. |
| ADR-020 | 2026-10-05 | Accepted | **Format presets are data** (`format_presets`, super-admin editable) with exact sizes, safe zones and copy limits. Every output is validated against its preset. Aspect changes use smart crop or outpaint — never stretch. | Platform specs change; wrong dimensions must be impossible, not just unlikely. |
| ADR-021 | 2026-10-05 | Accepted | Text, logos, CTA buttons and subtitles on **video** are burned in by Postaja (Satori overlay PNG + ffmpeg), extending ADR-009 to video. Clean (overlay-free) image and video assets are always stored. | Same reasons as ADR-009; clean assets make text edits, animation and recompose free of regeneration cost. |
| ADR-022 | 2026-10-05 | Accepted | **Every output** passes three rule layers — platform (global `platform_rules` + `format_presets`), channel, brand — most strict wins; checked in prompt, after generation and live in the editor by one shared rule engine. Hard violations block `ready` unless overridden with a logged reason. | Classic posts must be as compliant as ads: dimensions, caption length, hashtag count. Platform limits change, so they are data. |
| ADR-023 | 2026-10-05 | Accepted | **Competitor research**: AI finds competitors via web search; collects only public, ToS-respecting sources (web, Meta Ad Library API, public pages) plus owner-uploaded screenshots; no login scraping. Learnings are adopt/reject items the owner approves into a CGP proposal. Generated posts are checked against competitor posts to avoid copying. | Learn from competitors without legal/ToS risk or plagiarism; owner stays in control of the CGP. |
| ADR-024 | 2026-10-05 | Accepted | Database migrations run **at container start** of the `web` role (`RUN_MIGRATIONS=1` → `drizzle` migrate, then server). Replaces "Kamal pre-deploy hook" in `02-ARCHITECTURE.md` §9. | Kamal hooks run on the deploying machine, not next to the DB; running in the new container is simple and keeps migrations tied to the image. Migrations stay backward compatible (expand → migrate → contract), so the old container keeps working during the switch. |
| ADR-025 | 2026-10-05 | Accepted | **dev runs on the owner's existing Hetzner VM** (4 vCPU / 8 GB / 80 GB, user `deploy`), shared with an existing app (must stay) and later volil.si. One kamal-proxy for all Kamal apps on the host; each app has its own service name, its own DB accessory without published ports, memory limits, and named volumes. Prod gets its own VM before launch. | Cheapest start; 8 GB is enough for web + Postgres + light worker. Video/LibreOffice work (phase 1b+) may need the worker on a separate VM. Requires ports 80/443 to be free for kamal-proxy (TASK-002 checks the existing app). |
| ADR-026 | 2026-10-05 | Accepted | On the shared server **kamal-proxy owns ports 80/443** (automatic Let's Encrypt per app); host nginx is retired. Every app on the host is deployed with Kamal: Postaja dev, volil.si, and **asisto is migrated to Kamal**. Transitional step: asisto-api is registered in kamal-proxy by hand until its own Kamal config exists. Supersedes the "nginx in front" option. | One proxy, one deploy tool, zero-downtime deploys and automatic TLS for every app; no hand-edited nginx/certbot per domain. Cost: a few minutes of asisto API downtime at cutover (asisto is not in active use) and a one-time migration. Nginx config is backed up and can be restored in minutes. |
| ADR-027 | 2026-10-05 | Accepted | **Supersedes ADR-026.** On the shared dev server **host nginx stays the edge** (80/443, certbot TLS). kamal-proxy runs behind it on `127.0.0.1:8080` only (`ssl: false`, `forward_headers: true`); nginx gets one `server` block per Kamal app (`dev-postaja.inzenirji.si`, later volil.si) proxying to it. asisto is not migrated. Postaja prod and volil.si prod get their own Kamal-only servers (kamal-proxy on 80/443). | The asisto repo shows `asisto.app` and `portal.asisto.app` are Laravel on host PHP-FPM — kamal-proxy cannot serve them without containerising two unused apps. Nginx in front changes nothing for asisto, costs one nginx block + certbot per new domain on this box only, and keeps prod servers clean. |
| ADR-028 | 2026-10-05 | Accepted | Auth v1 (refines ADR-004 and ADR-013): **magic link only** (no passwords yet), **no public sign-up** — an account can be created only for emails in `SUPERADMIN_EMAILS` (bootstrap) or, from TASK-003b, with a pending organization invitation; enforced in the Better Auth `user.create.before` DB hook and in `sendMagicLink` (unknown emails get no mail, same API answer). Super admin = `user.role` additional field (`input: false`), **not** the Better Auth admin plugin; admin endpoints are ours (audited, TASK-003c). Tokens stored hashed, valid 10 min, single use. Email via **SMTP** (`mail.datavallis.com:465`, from `hello@inzenirji.si`) with nodemailer — replaces `EMAIL_PROVIDER_API_KEY` in the architecture. | Smallest attack surface for an invite-only B2B tool; the admin plugin would expose impersonation/ban endpoints we do not want yet. Owner already runs a mail server. |
| ADR-029 | 2026-10-05 | Accepted | Organizations (refines ADR-005): org ids are Better Auth **text** ids, so tenant tables use `org_id text` (not uuid). Org roles **owner / editor** (own access control; org deletion disabled). Organizations are created **only by super admins** via `src/server/orgs/service.ts` (`allowUserToCreateOrganization: false`). Owners invite editors through Better Auth. **Pending invitations are accepted automatically at sign-in** (session create hook) and the first membership becomes the active org. `resolveOrgContext` re-verifies membership and `org_settings.status` on every request; `forOrg` is the only tenant data access path. | Matches Better Auth's id format; invite-by-email + magic link gives a one-click join without a separate accept screen; membership re-check stops a forged `activeOrganizationId`. |
| ADR-030 | 2026-10-05 | Accepted | Platform rules and format presets are seeded from researched public sources with **source, confidence (high/medium/low) and verified date per row**. When sources disagree, the **stricter value** is seeded and the conflict is written in `notes` (e.g. Instagram hashtags 5 vs 30 → 5; carousel 10 vs 20 → 10; TikTok caption 2,200 vs 4,000 → 2,200). Seeds use `ON CONFLICT DO NOTHING` so super-admin edits are never overwritten. The rule engine (`src/lib/rules`) is dependency-free and shared by server and browser; X weighted counting is implemented in-house (no twitter-text). | A stricter limit can never produce a post the platform rejects; recorded sources make every number checkable; no new dependency for ~40 lines of counting. |
| ADR-031 | 2026-10-05 | Accepted | Brands: configuration (create, edit, CGP/profile, channels, archive) is **owner-only**; editors read. Profile versions are **immutable**; each save inserts version max+1 under a row lock on the brand (concurrent saves serialize). Brands are archived, never deleted. Brand websites accept only `http(s)` URLs. Channel default format must be an enabled preset of the same platform. | Matches spec §2 roles; posts will reference the exact profile version they were generated with; `javascript:` URLs found by tests would be XSS when rendered. |
| ADR-032 | 2026-10-05 | Accepted | Platform data editing (TASK-004b): super admins edit platform rules and format presets in `/admin/platform/*` through `src/server/rules/admin.ts` — validated (whole numbers, visible ≤ caption max, min ≤ max, safe zone leaves ≥ 1 px, verified date not in the future), row-locked, one `audit_log` row (`platform_rule.update` / `format_preset.update`) with `{field: {from, to}}` per changed field; unchanged saves write nothing. Key, platform, placement and media of a preset are fixed; presets are **disabled, never deleted** (later generations reference keys); no new rows from the UI yet. **Quarterly re-verification** = a row whose `verified_at` is **≥ 90 days old** is due; v1 reminder is an in-app banner on `/admin` and `/admin/platform` plus a per-row badge (no email/cron yet — no scheduler exists). | Platform specs change; editing must be safe and traceable. Disable-not-delete keeps history valid. An in-app reminder needs no new infrastructure; email reminders can be added with the job runner. |
| ADR-033 | 2026-10-05 | Accepted | Brand file uploads (TASK-005b, refines ADR-006): uploads go **through the app** (not presigned PUT) so bytes are checked before they are stored. Type from **magic bytes** only (PDF, OOXML docx/xlsx/pptx by ZIP part names, PNG/JPEG/WebP, TTF/OTF, UTF-8 text; CSV vs text by name since both are text). **No SVG** (script risk) and no legacy .doc/.xls/.ppt, no WOFF/WOFF2 (Satori). Images are decoded and re-encoded by sharp (metadata stripped, ≤ 40 MP input, logos PNG ≤ 2048 px, others PNG/JPEG ≤ 4096 px). Fonts are parsed in-house (cmap/name); a brand writing `sl` refuses fonts missing any of `č š ž ć đ Č Š Ž Ć Đ`. Limits: logo/font 10 MB, source 50 MB; per brand 10 logos, 20 fonts, 200 sources; same file twice per brand = duplicate (sha256 of the upload). **Tenant separation:** keys `org/<orgId>/brand/<brandId>/<kind>/<uuid>.<ext>` built only from verified ids; rows (`brand_sources`, `brand_assets`) are the source of truth and are read only via `forOrg`; URLs are presigned (default 5 min, max 15) only after the row is found in the caller's org. Upload/delete = brand owner; read/download = any member. S3 put then row insert; a failed insert deletes the object; delete removes the row first. Local/CI S3 stand-in: moto server (MinIO no longer publishes community images). | The owner requires strict per-organization separation; checking content server-side is the only way to keep executables, scripts and decompression bombs out; in-house sniffing/font parsing avoids three dependencies for ~250 tested lines. |
| ADR-034 | 2026-10-06 | Accepted | Smart uploads (TASK-005c, refines ADR-033 on owner feedback): one drop zone for everything. The server sorts each file (fonts → fonts, images with "logo" in the name → logos, rest → sources; a "Dodaj logotip" button forces the logo slot). A plain **ZIP is unpacked server-side** with hard limits (≤ 200 files, ≤ 50 MB each, ≤ 300 MB total, ZIP ≤ 100 MB, inflation capped regardless of headers; encrypted/ZIP64/nested ZIPs refused per entry). **WOFF and WOFF2 are accepted** and converted to TTF/OTF on upload (WOFF in-house, WOFF2 via `wawoff2`, MIT) because the renderer needs TTF/OTF; this supersedes the "no WOFF/WOFF2" part of ADR-033. SVG stays refused. The diacritics requirement and note apply only to brands with `sl`. A channel's language must be one of its brand's languages. | Owner: brands ship web fonts and folders of assets; sorting files by hand was poor UX; an English brand got Slovenian defaults. Conversion at upload keeps rendering simple (one font format). |
